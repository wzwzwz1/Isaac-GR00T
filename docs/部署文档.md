# GR00T-N1.6-3B 昇腾NPU部署总结

## 概述

将 NVIDIA GR00T-N1.6-3B (Vision-Language-Action 机器人基础模型) 从 CUDA 生态迁移至华为昇腾 Ascend 310P3 NPU 上运行推理。

## 核心挑战与解决方案

### 挑战1: flash_attn 不可用

**问题**: 模型代码强依赖 CUDA Flash Attention (`flash_attn-2.7.4.post1`), ARM64 + Ascend NPU 环境下无法编译安装。

**解决**:
- 修改 `gr00t/model/modules/eagle_backbone.py`: 将 `attn_implementation` 从 `"flash_attention_2"` 改为 `"sdpa"`，并移除强制断言
- 修改 `gr00t/model/modules/nvidia/Eagle-Block2A-2B-v2/modeling_eagle3_vl.py`: 移除 Qwen3/SigLIP2 对 flash_attention_2 的强制要求，添加 sdpa fallback
- 修改 `/root/models/GR00T-N1.6-3B-FP16/config.json`: `"use_flash_attention": false`

### 挑战2: BF16 → FP16 转换

**问题**: Ascend 310P3 硬件对 bfloat16 支持有限（通过软件模拟），且内部可能有 BF16→FP32 隐式转换，影响性能。模型权重原本以 BF16 存储。

**解决**:
- 编写权重转换脚本，将 2 个 safetensors 分片 (6.1GB) 从 bfloat16 转为 float16
- 修改 `config.json`: `"torch_dtype": "float16"`, `"load_bf16": false`, `"model_dtype": "float16"`
- 修改 `gr00t/policy/gr00t_policy.py`: 模型加载和设备转移时使用 `torch.float16`

### 挑战3: F.scaled_dot_product_attention NPU 不兼容

**问题**: Ascend 310P3 上调用 `F.scaled_dot_product_attention` 报错 `"can not cast format when output is input"`，这是 NPU 不支持 SDPA in-place 类型转换导致。

**解决**:
- 在推理入口 (server.py, test_inference.py) 中 monkey-patch `F.scaled_dot_product_attention`
- 替换为手动实现的 attention: `matmul(softmax(matmul(Q, K.T) / sqrt(d) + mask), V)`
- 这是精度完全等价的标准 attention 实现，但无 Flash Attention 的 IO-aware 优化

### 挑战4: Python 3.9 兼容性

**问题**: Isaac-GR00T 代码使用 PEP 604 语法 (`X | None`)，要求 Python ≥ 3.10，但系统仅有 Python 3.9.9。

**解决**:
- 编写自动化脚本扫描所有使用 `|` 类型联合语法的文件 (共 38 个)
- 在每个文件顶部添加 `from __future__ import annotations`
- 关键修复文件: `gr00t/data/types.py`, `gr00t/configs/*.py`, `gr00t/policy/*.py` 等

### 挑战5: transformers 版本兼容

**问题**: Eagle-Block2A-2B-v2 模型代码依赖特定版本的 transformers API:
- `VideoInput` 类型在 transformers 4.57.6 中不存在
- `BASE_IMAGE_PROCESSOR_FAST_DOCSTRING` 在新版本中已移除
- `initializer_range` 属性在某些配置中缺失

**解决**:
- `processing_eagle3_vl.py`: 使用 try/except 处理 `VideoInput` 导入，fallback 到 `ImageInput`
- `modeling_eagle3_vl.py`: 使用 `getattr(self.config, 'initializer_range', 0.02)` 提供默认值
- `gr00t_n1d6.py`: 将 DataCollator 创建改为 try/except，推理时跳过（仅训练需要）

### 挑战6: triton 不可用

**问题**: ARM64 平台无 triton 3.3.1 wheel。

**解决**:
- 使用 `pip install -e . --no-deps` 跳过 triton 依赖
- triton 仅用于训练优化，推理不需要

## 部署结果

### 推理性能

| 指标 | 数值 |
|------|------|
| **平均延迟** | 304.6 ms |
| **最小延迟** | 295.2 ms |
| **最大延迟** | 314.1 ms |
| **吞吐量** | 3.3 Hz |
| **NPU显存占用** | 5.57 GB |

### 与 NVIDIA GPU 对比

| 硬件 | 延迟 | 吞吐量 |
|------|------|--------|
| RTX 5090 (torch.compile) | 37 ms | 27.3 Hz |
| RTX 4090 (torch.compile) | 44 ms | 22.8 Hz |
| H100 (torch.compile) | 38 ms | 26.3 Hz |
| Jetson Thor (torch.compile) | 105 ms | 9.5 Hz |
| **Ascend 310P3 (本方案)** | **304 ms** | **3.3 Hz** |

> 310P3 比 NVIDIA GPU 慢约 8-10x，这符合预期：310P3 是推理卡（32 TOPS@INT8），非训练卡，且手动 SDPA attention 的 IO 开销远大于 Flash Attention。若使用 ATC 工具链将模型编译为 OM 格式，预期可获得 2-3x 加速。

### 动作输出验证

- 输出形状: `[1, 50, 128]` (batch=1, action_horizon=50, action_dim=128)
- 4 步流匹配去噪 (num_inference_timesteps=4)
- 动作范围为归一化值，需通过 processor 反归一化到物理关节空间

## 已知限制

1. **仅推理不支持训练**: DataCollator 和 Processor 完整 pipeline 因 transformers 版本兼容问题不可用，当前仅支持 backbone 特征级别的推理
2. **手动 SDPA 性能**: 手工实现的 attention 取代 Flash Attention，IO 效率较低，延迟约 300ms
3. **无完整 Processor Pipeline**: 原始图像和文本需通过外部 Eagle VLM Processor 预编码为 backbone 特征
4. **Python 3.9**: 通过 `from __future__ import annotations` 兼容，长期建议升级到 Python 3.10+
5. **310P3 BF16 支持**: 虽可创建 BF16 tensor，但底层可能通过软件模拟，推荐使用 FP16

---

## 后续优化方向

1. **ATC 模型编译**: 使用 Ascend Tensor Compiler 将 DiT 部分编译为 OM 格式，预期 2-3x 加速
2. **NPU 算子优化**: 针对 manual attention 实现 Ascend C 自定义算子
3. **Processor 适配**: 修复 transformers 版本兼容问题，恢复完整的 VLA pipeline
4. **多卡并行**: 利用 4 卡 8 芯片做 batch 并行推理，提升总吞吐量
5. **Python 升级**: 升级到 Python 3.10+ 可移除所有 `__future__` 兼容性补丁
