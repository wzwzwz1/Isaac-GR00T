4. 优化建议 (按优先级排序)

[P1] ATC 模型编译 (OM 格式)

使用昇腾 ATC (Ascend Tensor Compiler) 将 DiT 模型编译为 OM 离线模型。310P3 的 ATC 可进行算子融合、常数折叠、内存规划，预期 2-3x 加速。

🔧 实施难度: 中 (2-3天) 📈 预期收益: 2-3x DiT 加速
实施步骤
  1. export DiT to ONNX (torch.onnx.export)
  2. atc --model=dit.onnx --framework=5 --output=dit_310p3 --soc_version=Ascend310P3
  3. 使用 ACL (AscendCL) C++ API 加载 OM 模型进行推理
  4. 注意: 需要将 DiT 从 Eagle backbone 中解耦, 分别推理

[P2] Ascend C 自定义 Attention 算子

当前使用手工 matmul+softmax+matmul 实现 attention, 三次独立 kernel launch 且中间 attention scores 矩阵全部读写 HBM。用 Ascend C 编写 fused attention kernel, 将 Q*K^T + softmax + *V 融合为单 kernel, 在 L1 buffer 中完成在线计算。

🔧 实施难度: 高 (1-2周) 📈 预期收益: DiT attention 部分 3-5x 加速
实施步骤
  1. 使用 Ascend C 编写 Flash-Attention-like kernel
  2. 利用 Tiling 将 QKV 分块加载到 L1 buffer
  3. 在 L1 中完成 online softmax + rescaling
  4. 通过 torch_npu.npu_jit_compile 或 pybind11 集成到 PyTorch

[P3] NPU 算子融合优化

torch_npu 提供了 npu_fused_attention 等融合算子。检查 torch_npu.npu_fused_attention 是否可以替代当前的手工 attention。此外对 AdaLayerNorm + Linear 等模式可以用 torch.compile(backend='aot_ts_npu') 或 torch_npu.npu_group_norm 融合。

🔧 实施难度: 低 (1-2天) 📈 预期收益: 10-20% 延迟降低
实施步骤
  1. 尝试 torch_npu.npu_fused_attention(Q, K, V)
  2. 对 DiT 内部的小算子使用 torch_npu.npu_fusion_attention
  3. 测试 torch.compile 在 NPU 上的效果 (实验性)

[P4] 减少去噪步数

当前 num_inference_timesteps=4。尝试减少到 2 或 3 步, 使用蒸馏或微调恢复动作质量。可将 DiT 延迟减半。

🔧 实施难度: 中 (需要重新训练/蒸馏) 📈 预期收益: 25-50% 总延迟降低
实施步骤
  1. 使用 1-2 步 teacher-forcing 蒸馏
  2. 或调整 noise schedule 为更高斯 (更少步数)
  3. 测试动作质量是否可接受

[P5] 多 Stream 并行 (Backbone + Action Head)

当前 backbone 和 action head 串行执行。如果有连续多帧推理, 可以使用双缓冲: backbone 处理下一帧时, action head 处理当前帧。

🔧 实施难度: 中 (3-5天) 📈 预期收益: ~30% 吞吐提升 (对单帧延迟无帮助)
实施步骤
  1. 使用 torch.npu.Stream 创建两个 stream
  2. 在 stream1 运行 backbone(next_frame), stream2 运行 action_head(current_frame)
  3. 通过 event 同步确保依赖关系

[P6] INT8 量化推理

310P3 的 INT8 算力为 32 TOPS, 与 FP16 相同。但 INT8 可以: 1) 减少 50% 显存占用; 2) 减少显存带宽压力; 3) 允许更大 batch。对 memory-bound 的 attention 操作可能有帮助。

🔧 实施难度: 中 (需要量化校准) 📈 预期收益: 10-20% 延迟降低 (attention 部分)
实施步骤
  1. 使用 NPU 量化工具 (amct) 对权重和激活进行 INT8 量化
  2. 校准数据集: 使用代表性的 backbone features
  3. 测试精度损失是否可接受

[P7] 减少 Eagle LLM 层数

当前 select_layer=16 (保留 16 层 LLM)。如果 backbone 耗时占比 > 40%, 可尝试 select_layer=12 或 8, 用更少的 LLM 层提取特征。对动作预测精度的影响需要通过实验验证。

🔧 实施难度: 低 (改配置即可) 📈 预期收益: 若 backbone 占 40%, 减少到 8 层可节省 ~20% backbone 延迟
实施步骤
  1. 修改 config.json 中 select_layer 值
  2. 重新加载模型测试精度
  3. 权衡延迟 vs 精度

5. 优化路线图 (推荐方案)

阶段1: 快速见效 (1-2周)

  1. Ascend C 自定义 Attention: 实现 Ascend C 版 Flash Attention → 预计 DiT attention 3-5x 加速
  2. 多 Stream 流水线: Backbone 和 Action Head 流水线并行 → 吞吐提升
